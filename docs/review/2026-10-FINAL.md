## Plain-English summary for Michael

**Your QR system is safe to keep using, and nothing about your printed QR codes changed.** All 16 printed codes still scan to the same github.io addresses, and all 16 campaign pages are byte-for-byte the same as before the fixes. The fixes are all in the control panel and the Mac scripts.

**What is now fixed:**

1. **A bad link can't hijack the control panel any more.** Before, a link with hidden code in it could quietly copy your GitHub key every time the panel opened, even after you changed the key. The panel now shows all campaign text as plain text.
2. **A bad link can't break a campaign page any more.** Links are cleaned before saving. A stray `"` or `<script>` can no longer send people to the wrong address or run code.
3. **The panel now has a "security lock" (a Content-Security-Policy).** The page can only run its own code files and can only send data to GitHub. Even if some future bug let foreign code in, the browser would block it and stop it from sending your key anywhere. I tested both: injected code was blocked, and a "send the key to another website" attempt was blocked.
4. **The Mac scripts are honest and careful.** They sync with GitHub first. They only say "Pushed" when the upload really worked; otherwise they say "PUSH FAILED — NOT live". They refuse bad links, bad campaign names, and the panel's own folders (`admin`, `logos`, `qr-codes`, `docs`). If you leave the link off, they ask you to paste it, so `&` and `?` in links no longer get cut off.
5. **Every QR is test-scanned before it's saved**, not just custom-colour ones. A QR that won't scan is refused.
6. **Safer key sharing.** If "Copy the link" fails, the link with your key stays hidden (dots) until you press **Show link**. The setup screen now recommends a **90-day** key instead of 1 year.
7. **Friendlier errors.** If a create half-fails, the campaign still shows in the list and the panel tells you to press "Restyle QR". "Already exists" and "must start with https:// (or http://)" messages are now plain English.

**What you need to do yourself:**

1. **Replace your GitHub key with a 90-day one (once, about 5 minutes).** On GitHub → Settings → Developer settings → Fine-grained tokens, create a new token named "QR panel", set Expiration to **90 days**, allow only the **Qr_code** repository, and give **Contents: Read and write**. In the panel, press **Change GitHub key** (bottom of the page) and paste it. Then delete the old token on GitHub. GitHub emails you before a key expires; repeat these steps when it does.
2. **Re-share access with anyone who had your old share link.** Deleting the old token locks out old links (that's the point). Make a fresh link from the panel's share card and send it privately (AirDrop or a password manager).
3. **On your Mac, run `git pull` once** in the Qr_code folder so you get the new scripts. After that they sync themselves.
4. **Open the panel once after this is live** (about 1 minute after merge): `https://michaello-ts.github.io/Qr_code/admin/`. If it loads your campaign list, everything is working. If it ever shows a blank page, tell Claude, but don't edit `admin/` files by hand.

**Risks that remain (by your choice, not bugs):** the key lives in the browser and is shared with colleagues by link. Anyone who gets a share link can change where QR codes point until you delete that key on GitHub. Git history keeps every old version, so any change can be undone. The 90-day key limits how long a leaked link works.
